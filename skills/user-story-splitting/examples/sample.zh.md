# 用户故事拆分示例

## 示例 1：按工作流步骤拆分

**原始故事：**
```markdown
### 用户故事 100：完成结账流程

**用例：**
- **作为** 购物者
- **我想要** 完成结账，包括输入配送、支付并确认订单
- **以便** 我可以收到我的物品

**验收标准：**
- **假设：** 我的购物车里有物品
- **当：** 我输入配送地址、支付信息并确认
- **则：** 我的订单被提交
```

**为什么需要拆分：** 多个工作流步骤捆绑在一起。

**使用工作流步骤拆分：**

```markdown
### 拆分 1：输入配送地址

**用户故事 101：**
- **摘要：** 结账时输入配送地址

**用例：**
- **作为** 购物者
- **我想要** 输入我的配送地址
- **以便** 我的物品被送到正确的地点

**验收标准：**
- **假设：** 我的购物车里有物品
- **当：** 我输入有效的配送地址并点击"继续"
- **则：** 我继续输入支付信息

---

### 拆分 2：输入支付信息

**用户故事 102：**
- **摘要：** 结账时输入支付信息

**用例：**
- **作为** 购物者
- **我想要** 输入我的信用卡信息
- **以便** 我可以为订单付款

**验收标准：**
- **假设：** 我已输入配送地址
- **当：** 我输入有效的支付信息并点击"继续"
- **则：** 我继续订单确认

---

### 拆分 3：确认订单

**用户故事 103：**
- **摘要：** 审核并确认订单

**用例：**
- **作为** 购物者
- **我想要** 审核我的订单详情并确认
- **以便** 我的订单被提交

**验收标准：**
- **假设：** 我已输入配送和支付信息
- **当：** 我审核订单摘要并点击"下订单"
- **则：** 我的订单被提交，我收到确认
```

---

## 示例 2：按验收标准复杂度拆分

**原始故事：**
```markdown
### 用户故事 200：管理团队成员

**用例：**
- **作为** 团队管理员
- **我想要** 管理团队成员
- **以便** 我可以控制访问

**验收标准：**
- **当：** 我添加成员，则他们收到邀请
- **当：** 我移除成员，则他们失去访问权限
- **当：** 我更改成员的角色，则他们的权限更新
```

**为什么需要拆分：** 多个"当/则"语句。

**使用验收标准复杂度拆分：**

```markdown
### 拆分 1：添加团队成员

**用户故事 201：**
- **摘要：** 邀请新团队成员

**用例：**
- **作为** 团队管理员
- **我想要** 邀请新成员加入我的团队
- **以便** 他们可以访问共享资源

**验收标准：**
- **假设：** 我有管理员权限
- **当：** 我输入电子邮件并点击"邀请"
- **则：** 收件人收到电子邮件邀请

---

### 拆分 2：移除团队成员

**用户故事 202：**
- **摘要：** 移除团队成员

**用例：**
- **作为** 团队管理员
- **我想要** 从我的团队中移除成员
- **以便** 他们不再有访问权限

**验收标准：**
- **假设：** 我有管理员权限
- **当：** 我点击成员旁边的"移除"
- **则：** 该成员立即失去访问权限

---

### 拆分 3：更改成员角色

**用户故事 203：**
- **摘要：** 更新团队成员角色

**用例：**
- **作为** 团队管理员
- **我想要** 更改成员的 role
- **以便** 他们的权限与他们的职责相匹配

**验收标准：**
- **假设：** 我有管理员权限
- **当：** 我为成员选择新角色并保存
- **则：** 他们的权限更新以匹配新角色
```
