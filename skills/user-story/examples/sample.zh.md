# 用户故事示例

## 示例 1：好的用户故事

```markdown
### 用户故事 042：

- **摘要：** 为试用用户启用 Google 登录以减少注册摩擦

#### 用例：
- **作为** 首次访问应用的试用用户
- **我想要** 使用我的 Google 账户登录
- **以便** 我可以访问应用而不必创建和记住新密码

#### 验收标准：

- **场景：** 首次试用用户通过 Google OAuth 登录
- **假设：** 我在登录页面上
- **而且假设：** 我有一个 Google 账户
- **而且假设：** "使用 Google 登录"按钮可见
- **当：** 我点击"使用 Google 登录"按钮并授权应用
- **则：** 我登录到应用并重定向到入门流程
```

**为什么有效：**
- 人物具体（"首次访问的试用用户"）
- 动作清晰（"使用我的 Google 账户登录"）
- 成果解释动机（"而不必创建新密码"）
- 验收标准可测试（QA 可以验证每个步骤）
- 只有一个当，一个则（范围适当）

## 示例 2：坏用户故事（太模糊）

```markdown
### 用户故事 999：

- **摘要：** 改进登录体验

#### 用例：
- **作为** 用户
- **我想要** 更好的登录
- **以便** 我可以使用应用

#### 验收标准：

- **场景：** 用户登录
- **假设：** 我想登录
- **而且假设：** 我有一个活跃账户
- **当：** 我登录
- **则：** 它更好地工作
```

**为什么失败：**
- "用户"太通用（试用用户？回访用户？管理员？）
- "更好的登录"不是动作（具体是什么？）
- "使用应用"不是具体成果（每个人都想使用应用）
- 验收标准不可测试（"更好地工作" = 不可衡量）

**如何修复：**
- 缩小人物："试用用户"、"没有密码管理器的回访用户"等
- 定义动作："使用 Google 登录"、"通过邮件重置密码"等
- 具体说明成果："而不必记住新密码"、"在 30 秒内"等
- 使验收标准可证伪："则我在 2 秒内重定向到仪表板"

## 示例 3：需要拆分的故事

```markdown
### 用户故事 100：

- **摘要：** 管理购物车

#### 用例：
- **作为** 购物者
- **我想要** 添加物品、移除物品、更新数量、应用优惠券，并结账
- **以便** 我可以完成购买

#### 验收标准：

- **场景：** 购物车管理
- **假设：** 我的购物车里有物品
- **当：** 我添加物品
- **则：** 它出现在购物车中
- **当：** 我移除物品
- **则：** 它从购物车中消失
- **当：** 我更新数量
- **则：** 购物车总数更新
- **当：** 我应用优惠券
- **则：** 折扣被应用
- **当：** 我结账
- **则：** 我继续付款
```

**为什么需要拆分：**
- 多个"当"语句 = 多个故事
- 范围太大，无法在单个 sprint 中完成
- 不同成果不相关（添加物品 ≠ 应用优惠券）

**如何拆分：**
使用 `skills/user-story-splitting/SKILL.md` 将其拆分为：
1. "将物品添加到购物车"
2. "从购物车移除物品"
3. "更新物品数量"
4. "应用折扣优惠券"
5. "结账并继续付款"

每个成为自己的故事，聚焦验收标准。
