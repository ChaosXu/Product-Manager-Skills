# 产品策略会议示例

### 示例 1：良好的产品策略会议（SaaS 入职改进）

**背景：** 现有 SaaS 产品有 60% 的入职流失，需要战略方法来解决留存问题。

**阶段 1 - 定位：**

- 运行 `positioning-workshop.md`：定义目标 = "非技术小企业主"
- 创建原型人物角色："Solo Entrepreneur Sam"（无 IT 支持）
- JTBD："帮助我快速从软件中获得价值，无需技术专业知识"

**阶段 2 - 问题框架：**

- 运行 `problem-framing-canvas.md`：问题 = "用户因为术语密集型 UI 和缺乏指导而放弃入职"
- 问题陈述："60% 的非技术用户在 24 小时内因令人不知所措的不清晰入职流程而流失"

**阶段 3 - 解决方案探索：**

- 运行 `opportunity-solution-tree.md`：生成 3 个机会（指导、简化、支持）
- 选择的机会："缺乏入职指导"
- 解决方案：引导式清单、工具提示、邮件滴灌、人工辅助入职
- POC：引导式清单（用原型测试）

**阶段 4 - 优先级排序：**

- 运行 `prioritization-advisor.md`：推荐 RICE（早期 PMF 阶段，有一些数据）
- 评分 Epic：引导式入职（RICE：12,000）、应用内帮助（8,000）、人工入职（3,000）
- 路线图：Q1 = 引导式入职，Q2 = 应用内帮助

**阶段 5 - 对齐：**

- 向高管展示：问题陈述 + OST + 路线图
- 反馈："我们能在完全构建之前运行实验吗？" → 添加 2 周原型测试

**阶段 6 - 执行：**

- 运行 `epic-breakdown-advisor.md`：使用工作流模式分解"引导式入职"
- 故事：R1 = 简单清单（3 步），R2 = 进度跟踪，R3 = 庆祝/游戏化
- 计划 Sprint 1：构建 R1（简单清单）

**成果：** 清晰、经过验证的策略，具有高管购买和可执行的路线图。

### 示例 2：糟糕的产品策略会议（跳过发现）

**背景：** 初创公司想要构建移动应用。

**阶段 1 - 定位：** 跳过（假设定位清晰）

**阶段 2 - 问题框架：** 跳过（跳到解决方案："我们需要移动应用"）

**阶段 3 - 解决方案探索：** 跳过（已经决定解决方案）

**阶段 4 - 优先级排序：** 构建特性列表，按"什么最容易"排序

**阶段 6 - 执行：** 立即开始构建移动应用

**为什么这失败了：**

- 没有定位验证（应用是给谁的？）
- 没有问题验证（客户实际上需要移动访问吗？）
- 没有探索替代解决方案（响应式 web？PWA？）
- 3 个月后：移动应用构建完成，使用率低，解决了错误的问题

**使用策略会议修复：**

- 运行定位工作坊：发现目标 = "无法访问桌面的现场工作人员"
- 运行问题框架：验证移动优先用户无法在旅途中完成工作流
- 运行 OST：探索替代方案（移动应用、响应式 web、PWA、SMS 通知）
- 运行实验：首先测试响应式 web（2 周），验证它解决了 80% 的问题
- 成果：构建响应式 web 而不是原生应用，节省了 2 个月的开发时间
