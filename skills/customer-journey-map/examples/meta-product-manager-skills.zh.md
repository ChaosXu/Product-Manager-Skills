# 客户旅程图示例

## 元狗粮示例：产品经理技能仓库

此示例有意映射我们自身仓库的旅程，以体现狗粮原则：我们使用与其他 PM 工件相同的质量标准。

```markdown
## 客户旅程图：AI 先行 PM 负责人（产品经理技能）

### 产品
产品经理技能（面向 Claude/Codex 代理工作流的开源 PM 技能库）

### 画像
- AI 先行 PM 负责人：B2B SaaS 公司（20-300 名员工）的 PM 负责人，对更快发现/交付负责，对 AI 炒作持怀疑态度，注重实用框架和可重用工作流

### 目标
- 提高 PM 技能在真实产品工作流中的合格采用
- 改善从发现到成功技能使用的首周激活
- 增加重复使用和贡献行为

| **阶段** | **认知** | **考虑** | **决策** | **服务** | **忠诚** |
|---|---|---|---|---|---|
| **客户动作** | 看到 LinkedIn/Substack 帖子、从同龄人听到关于仓库的消息、搜索 Claude/Codex 的 PM 技能 | 阅读 README、扫描技能目录、与提示库比较、查看文档 | 克隆仓库、选择 1-2 个技能、运行第一个引导流程、评估输出质量 | 在规划/发现周期中使用多个技能、调整输出、内部分享 | 重复使用作为默认 PM 操作层、推荐给同龄人、打开 issues/PR |
| **触点** | LinkedIn 帖子、Substack、GitHub 仓库/搜索、社区提及 | README、CLAUDE.md、使用文档、单个 SKILL.md 文件 | 终端/Codex/Claude 会话、技能文件、辅助脚本、快速入门文档 | 技能工作流、脚本、文档、发布说明、提交历史 | GitHub issues/PR、发布说明、文档更新、公告 |
| **客户体验** | 好奇但怀疑："这是实用的还是仅仅是提示表演？" | 感兴趣但超载："我应该先使用哪个技能？" | 充满希望但焦虑："这在我的真实环境中可行吗？" | 当输出可重用时感到轻松；当行为不一致时感到沮丧 | 自信和投入："这给我的团队带来了可重复的优势。" |
| **KPI** | GitHub 页面浏览量、独立访客、推荐来源组合、每位访客的星标率 | README 到文档点击率、文档停留时间、技能页面打开数、首次安装意图 | 首次运行成功率、首次可用输出时间、设置流失、48 小时内返回 | 周活跃用户（代理）、多技能使用率、工作流完成率、破碎模式问题率 | 重复贡献者数量、PR 数量/质量、推荐流量、活跃用户留存 |
| **业务目标** | 触达合格的 PM/PMM/创始人受众，定位为实用和代理就绪 | 减少认知负担，帮助用户快速选择正确的第一个技能 | 最小化设置摩擦，在首次会话中证明价值 | 保持跨技能的一致质量，增加工作流级别的采用 | 建立贡献者飞轮并通过一致性建立信任 |
| **涉及的团队** | 内容/作者、社区、维护者 | 维护者、文档所有者、技能作者 | 维护者、贡献者、工具/脚本维护者 | 技能作者、审查者、维护者 | 核心维护者、贡献者、社区倡导者 |

### 分析
**前 3 个优先机会：**
1. 首个技能入职路径：添加"从这里开始（15 分钟）"流程，将画像映射到前 3 个推荐技能
2. 一致性护栏：保持共享促进规则集中并自动检查所有链接技能
3. 激活工具化：定义首次运行成功和多技能采用的轻量级指标

### 需要验证的假设
1. 主要画像是 B2B SaaS 团队的 PM 负责人
2. 大多数发现流量从 GitHub 加社交内容开始
3. 最大摩擦是"先选哪个技能？"加上跨技能一致性
```
